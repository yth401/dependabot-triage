# dependabot-triage

Dependabot alerts のアラートを、「このプロジェクトで実際に対処が必要か」で振り分ける Claude Code プラグインです。

## これは何か

Dependabot alerts は、依存しているライブラリに脆弱性が見つかると知らせてくれます。ただ、そのアラートが自分のプロジェクトで本当に問題になるかは、人が調べて決める必要があります。たとえば、Web フレームワークのサーバー側（SSR）の脆弱性は、静的サイトとして配信しているだけのプロジェクトには関係ありません。

dependabot-triage は、この調べものを Claude に任せるためのものです。

- 開いているアラートを 1 件ずつ、プロジェクトの事情（プロジェクトの種類、公開範囲、`guidance.md` に書いた事情）を踏まえて判定します
- 結果は「要対処」「不要」「不明」のどれかと、このプロジェクトでの深刻度（緊急／高／中／低）、その根拠です
- 「不要」なら、理由を付けてアラートを閉じます。「要対処」なら、Issue にするか、期限付きで保留にするかを選べます
- アラートを閉じる・Issue を作るといった操作は、必ずあなたの確認をとってから行います

できないこと：

- 脆弱性の検出はしません。検出と通知は Dependabot が行います。対応する言語やパッケージ管理ツールも Dependabot と同じです

## 必要なもの

- 使うリポジトリで Dependabot alerts が有効になっていること
- PC に Claude Code、git、GitHub CLI（`gh`）が入っていること
- `gh` でログインしていて、トークンに `security_events` のスコープがあること（足りなければ `gh auth refresh -s security_events`）
- 使うリポジトリでの役割が Write 以上であること（Read と Triage ではアラートを閉じられません）

## 導入

### 1. プラグインをインストールする

Claude Code で次を実行します。

```
/plugin marketplace add yth401/dependabot-triage
/plugin install dependabot-triage@dependabot-triage
```

### 2. 初期設定をする

使うリポジトリで `/dependabot-triage:init` を実行します。

Claude がリポジトリを読んで、プロジェクトの種類や公開範囲の当たりを付け、判定のときに考慮してほしい事情の案を作ります。そのうえで、次のことを聞かれます。

- プロジェクトの種類（プリセット）と公開範囲
- 判定のときに考慮してほしい事情（Claude が作った案を確かめて直します）
- どのアラートを判定の対象にするか（閾値）と、深刻度ごとの対処期限
- 「要対処」のものを Issue にするか、結果を見るだけにするか

答えると、次のファイルができます。

- `dependabot-triage.yml`：設定
- `.dependabot-triage/guidance.md`：判定のときに考慮してほしい事情
- `.claude/settings.json`：チームのメンバーが、このリポジトリを開いたときにプラグインのインストールを促されるようにする設定

### 3. コミットする

init はコミットも push もしません。できたファイルを確かめて、コミットしてください。チームで同じ設定を使うことになります。

## 使い方

Dependabot からアラートの通知が来たら、使うリポジトリで `/dependabot-triage:check` を実行します。特定のアラートだけを見たいときは、`/dependabot-triage:check 42` のように番号を渡します。

最初にまとめが出て、そのあとに 1 件ずつの結果が出ます。

| 要否 ＼ 深刻度 | 緊急 | 高 | 中 | 低 | − | 計 |
|---|---|---|---|---|---|---|
| 要対処 | 1 | 0 | 1 | 0 | 0 | 2 |
| 不明 | 0 | 1 | 0 | 0 | 0 | 1 |
| 不要 | 0 | 0 | 0 | 0 | 2 | 2 |

| 判定しなかったもの | 件数 |
|---|---|
| 起票済（Issue がある） | 4 |
| 閾値で対象外 | 4 |

結果を見たあと、次のことを決めます。

| 結果 | あなたが決めること |
|---|---|
| 要対処 | Issue にする、期限付きで保留にする、何もしない、のどれか |
| 不要 | 示された理由でアラートを閉じてよいか |
| 不明 | Claude は何もしません。あなたが調べて決めてください |

### アラートの状態の考え方

アラートを閉じるのは「不要」のものだけです。対処が必要なものと保留中のものは、開いたまま残ります。そのため、開いているアラートの数が、そのまま「まだ片づいていない作業」の数になります。

### 期限付きの保留

「今は直せないが、期限までは待てる」というものは、要対処の確認のときに保留を選び、理由と期限を入れます。

- 保留の Issue が作られます。アラートは閉じません
- 期限までは check の判定に回りません。期限が過ぎると、もう一度判定されます
- 保留をやめるときは、その Issue を閉じます

## 設定

`/dependabot-triage:settings` で、今の設定の表示、確認、変更ができます。ファイルを直接直してもかまいません。

### プリセット

プロジェクトの種類を 1 つ選びます。合うものがなければ、いちばん近いものを選び、違うところを `guidance.md` に書きます。

| プリセット | 想定するプロジェクト |
|---|---|
| `web-service` | インターネットに公開している、サーバーのある Web サービス |
| `internal-service` | 認証の内側や社内ネットワークからだけ使う、サーバーのあるサービス |
| `static-site` | ビルドして静的なファイルを配信するサイト |
| `library` | ほかのプロジェクトに組み込まれるパッケージ |
| `cli-tool` | 手元や CI で動かすコマンドやバッチ |

### guidance.md

判定のときに考慮してほしい事情を、自由に箇条書きで書きます。具体的に書くほど、判定が正確になります。

```markdown
- 管理画面（/admin）は社内ネットワークからしか開けない
- 利用者がアップロードした画像を、サーバーで縮小している
- CI はフォークからの PR では動かない
```

### 閾値と対処期限

- 閾値を下回ったアラートは判定されません（アラートは開いたまま残ります）。Dependabot の深刻度はプロジェクトの使い方を考慮しない値なので、取りこぼしたくなければ低めにしてください
- 対処期限は、このプロジェクトでの深刻度ごとに日数で決めます（推奨：緊急＝当日、高＝7 日、中＝30 日、低＝期限なし）

項目の一覧は [設定の仕様](reference/config.md) にあります。

## 判定の前提

判定には、次の前提を置いています。プロジェクトに合わなければ、`guidance.md` に書いてください。

- **リポジトリに書き込める開発者は信頼します**：開発者だけが悪用できる脆弱性は「不要」とします。ただし、開発者のブラウザや PC が外から操られるもの（外部のサイトを開くだけで開発用サーバーに届く、など）や、悪意のあるパッケージは対象にします
- **社内向けのサービスでも、利用者からの攻撃はありうるものとします**：利用者の PC やアカウントが乗っ取られることがあるためです
- **わからないものは「不要」にしません**：コードを検索して見つからなかったというだけでは「使っていない」とはせず、「不明」にします

判定の細かい決まり（観点、深刻度の上げ下げ）は [判定の基準](skills/check/criteria.md) にあります。
